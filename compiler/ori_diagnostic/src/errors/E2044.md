# E2044: Pre-Condition Contract Type Must Be `bool`

A `pre(condition)` clause was attached to a function, and its `condition`
expression did not type-check to `bool`. Pre-condition predicates are evaluated
on entry and must reduce to a single boolean answer ("contract holds"
vs. "contract violated") — the runtime cannot panic on a non-boolean.

## Cause

`pre()` accepts an expression that the type checker resolves against the
expected type `bool`. Common slips that produce E2044:

```ori
@withdraw (amount: int) -> int
    pre(amount)                  // E2044 — `int`, not `bool`
    pre(amount + 0)              // E2044 — arithmetic result is `int`
    pre(Some(amount))            // E2044 — `Option<int>`, not `bool`
    = { ... }
```

The diagnostic reports the actual inferred type plus the expected `bool`, with
the contract clause as the expected-origin context.

## Cure

Wrap the value in a comparison or call a predicate that returns `bool`:

```ori
@withdraw (amount: int) -> int
    pre(amount > 0)                   // OK — comparison yields `bool`
    pre(amount > 0 | "must be positive")  // OK — message form, still `bool`
    = { ... }
```

The pipe-message form `pre(cond | "message")` does not change the type rule —
the LHS of `|` still has to be `bool`. The string literal is the panic message
emitted on contract failure.

# E2048: EDROP_PARTIAL_MOVE — Partial Move on Type Implementing Drop

A field of a type implementing `Drop` was partially moved out via a `let`
binding. Types implementing `Drop` cannot be partially moved because the
compiler-walked field drop after the user `@drop` body would see absent
fields, breaking the Drop trait's invariant that `@drop (self) -> void`
runs against a fully-valid `self`.

## Cause

The shape rejected is `let $f = v.field` where `v`'s type implements `Drop`:

```ori
type Resource = { handle: int, name: str }

impl Resource: Drop {
    @drop (self) -> void = print(`closing-{self.name}`)
}

@example (r: Resource) -> str = {
    let n = r.name      // ERROR: partial move on Drop type `Resource`
    n
}
```

Per `drop-trait-proposal.md §Execution Timing`, the compiler walks `Resource`'s
owned fields in reverse declaration order AFTER invoking `Resource::@drop(r)`.
If `r.name` was moved out before the drop body fired, the field walk would
encounter an absent string and either double-free or read freed memory.

The restriction is uniform — it applies to every partial-move shape of every
`Drop` type, regardless of which CFG path the move appears on. Contrast with
`E2043` (`EBURDEN_CONDITIONAL_PARTIAL_MOVE`), which rejects only the *conditional*
partial-move shape (asymmetric across branches) for non-Drop aggregates;
E2048's axis is disjoint: every `Drop` partial move is forbidden, whether the
move is unconditional or conditional.

Closure-capture sites are bindings too — capturing a partially-moved field of
a `Drop` type produces the same E2048 diagnostic.

## Cure

Three idiomatic alternatives consume a `Drop` value without partial-moving a
field:

1. **Full move** — consume the entire value at once:

   ```ori
   @example (r: Resource) -> str = {
       let owned = r    // entire `r` moved into `owned`
       owned.name        // field access on owned value (no partial move)
   }
   ```

2. **Borrow / read-only field access** — read a field without binding it as a
   move:

   ```ori
   @example (r: Resource) -> int = r.name.length()
   ```

   Field access used as a read-only operand (call argument, comparison,
   spread expression) does not move the field — only `let $f = v.field`
   bindings do.

3. **Match destructure** — destructure all fields simultaneously, consuming
   the whole value:

   ```ori
   @example (r: Resource) -> str = match r {
       Resource { handle, name } -> name,
   }
   ```

   Match-binding all fields together consumes the entire value at once; no
   field is "partially" moved relative to its siblings.

If the goal was to defer the drop, use `drop_early(value: r)` (per
`spec/08-types.md`) to invoke `r`'s drop body immediately; subsequent code
must not reference `r`.

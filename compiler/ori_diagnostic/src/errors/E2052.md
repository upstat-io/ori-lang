# E2052: Or-Pattern Alternatives Bind Different Variable Names

The alternatives of an or-pattern (`A | B`) bind different sets of variable
names. Every alternative of an or-pattern must bind exactly the same names, so
the match arm body sees a consistent set of bindings no matter which
alternative matched.

## Example

```ori
@f (r: Result<int, int>) -> int = match r {
    Ok(n) | Err(m) -> 0,  // ERROR: `n` and `m` are each bound on only one side
    _ -> 1,
}
```

## Explanation

An or-pattern matches if any alternative matches, and the arm body runs with
whatever bindings that alternative produced. If a name is bound on only some
alternatives, the body could reference a name that is unbound on the path that
actually matched — reading an undefined binding slot. The type checker rejects
this at compile time (Spec: Clause 15, patterns).

## Fix

Bind the same names in every alternative:

```ori
@f (r: Result<int, int>) -> int = match r {
    Ok(n) | Err(n) -> n,  // both alternatives bind `n`
    _ -> 1,
}
```

Or, if the alternatives genuinely carry different data, split them into
separate arms.

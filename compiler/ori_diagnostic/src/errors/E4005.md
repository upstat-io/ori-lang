# E4005: Contract Coherence Violation

The inferred memory contract for a function disagrees with what the
ARC realization pipeline actually emitted. This is a compiler bug —
the analysis was more optimistic than the realization.

This error is only reported when `ORI_VERIFY_ARC=1` is set. It is
detected by the contract coherence oracle, which walks the post-pipeline
ARC IR and re-derives the contract from actual RC operations.

## Example mismatches

- **Access**: contract says `Borrowed` but the IR contains `RcInc`/`RcDec`
  for the parameter (the parameter is actually `Owned`)
- **Consumption**: contract says `Linear` but the IR has both `RcInc` and
  `RcDec` (the parameter is actually `Unrestricted`)
- **Effects**: contract says `may_deallocate = false` but the pipeline
  detected missed reuses

## What to do

File a bug report. This indicates a mismatch between the interprocedural
analysis (`analyze_program`) and the realization pipeline (steps 5-12).

# E4004: FBIP Enforcement Violation

A function annotated with `#fbip` has missed constructor reuse opportunities.

## Example

```ori
#fbip
@transform (node: Tree) -> Tree = {
    // If the compiler cannot prove in-place reuse for all
    // constructors, this error is raised.
    Tree { left: node.right, right: node.left }
}
```

## Explanation

The `#fbip` (Functional But In-Place) attribute asserts that all constructor
allocations in the function will be eliminated by the reset/reuse optimization.
When the ARC pipeline detects constructors that could not be reused in place,
it reports this violation.

FBIP is a Koka-inspired optimization: if a data structure's reference count is
1 (unique), the old allocation can be reused for the new constructor, achieving
in-place mutation semantics with functional syntax.

## Fix

Ensure the function's data flow allows the compiler to prove uniqueness for all
constructed values. Common blockers:

- Sharing the input (passing it to multiple consumers)
- Capturing the input in a closure
- Conditional branches where only one path reuses the allocation

Remove the `#fbip` annotation if in-place reuse cannot be guaranteed.

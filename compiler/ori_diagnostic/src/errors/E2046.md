# E2046: Post-Condition Contract Cannot Apply to Void-Returning Function

A `post(...)` clause was attached to a function whose declared (or inferred)
return type is `void`. A void-returning function produces no result for the
post-condition lambda to bind, so the contract has nothing meaningful to
verify.

## Cause

`post()` always takes a lambda whose parameter is the function's result. When
the function returns `void`, that parameter is uninhabited:

```ori
@log (msg: str) -> void
    post(r -> r != "")           // E2046 — no `r` to bind on a void return
    = { print(msg:) }
```

The check runs after the body type-check completes so the inferred return
type is fully resolved before the rejection fires.

## Cure

Either change the function to return the value the contract is asserting
about, or move the post-condition into the body as a runtime assertion:

```ori
@log (msg: str) -> str            // return the value the contract verifies
    post(r -> r != "")
    = { print(msg:); msg }

@log (msg: str) -> void           // OR drop the post-condition
    = { assert(msg != ""); print(msg:) }
```

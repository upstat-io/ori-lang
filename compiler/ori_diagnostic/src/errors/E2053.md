# E2053: Or-Pattern Alternatives Bind a Name at Different Types

A name bound by every alternative of an or-pattern (`A | B`) has a different
type across alternatives. A name shared by all alternatives must have the same
type in each, so the match arm body sees a single well-defined type for it.

## Example

```ori
type Mixed = AsInt(v: int) | AsStr(v: str);

@f (x: Mixed) -> int = match x {
    AsInt(v) | AsStr(v) -> 0,  // ERROR: `v` is `int` on one side, `str` on the other
}
```

## Explanation

When a name is bound on every alternative but at incompatible types, the arm
body cannot be given a single coherent type for it. The type checker requires
identical binding types across or-pattern alternatives (Spec: Clause 15,
patterns).

## Fix

Reconcile the types so the shared name has one type in every alternative, or
split the alternatives into separate arms that handle each type:

```ori
@f (x: Mixed) -> int = match x {
    AsInt(v) -> v,
    AsStr(s) -> s.length(),
}
```

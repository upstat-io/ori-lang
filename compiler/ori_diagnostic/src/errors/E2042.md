# E2042: Extern Type Passed As Owned Without `#free` Annotation

An `extern "c"` (or `extern "js"`) opaque type was used in an Owned position
without declaring a `#free(symbol)` annotation on its extern block. Opaque FFI
types whose lifetime is managed by Ori MUST name the deallocation function so
the compiler can emit a correct drop. Otherwise the type is treated as
caller-managed (no drop emitted) — passing it as Owned would silently leak.

## Cause

`extern "c" from "lib" { type Handle }` declares an opaque foreign type whose
storage lifetime is unknown to Ori. Without an annotation, the type carries an
empty burden (`BuiltinBurdenSpec::EMPTY`): no fields, no variants, no drop.
Such types are safe to pass as Borrowed, but passing them as Owned has no
defined cleanup path.

## Cure

Add a `#free(symbol)` annotation naming the deallocation function:

```ori
// Error: DbHandle used in Owned position without #free
extern "c" from "libsqlite" {
    type DbHandle
}

@close (db: DbHandle owned) -> void  // E2042

// Correct: #free names the deallocation function
extern "c" from "libsqlite" #free(sqlite3_close) {
    type DbHandle
}

@close (db: DbHandle owned) -> void  // OK — drop emits sqlite3_close(db)
```

If the extern type is truly caller-managed, restructure the API so it never
appears in an Owned position — pass it as Borrowed instead.

## Ori Context

Ori is a statically-typed, expression-based language with HM type inference, ARC memory management, capability effects, and smart testing. The compiler is written in Rust (Salsa-based) and targets LLVM/WASM.

Key paths:
- docs/ori_lang/v2026/spec/ — authoritative spec (grammar.ebnf, operator-rules.md)
- plans/roadmap/ — roadmap sections
- plans/ — other plans
- docs/ori_lang/proposals/ — proposals
- library/std/ — stdlib
- compiler/oric/ — compiler entry
- tests/spec/ — conformance tests

Reference compilers: ~/projects/reference_repos/lang_repos/ (Rust, Go, Zig, TS, Gleam, Elm, Roc, Swift, Koka, Lean 4)

Compiler architecture: oric -> ori_types/eval -> ori_parse -> ori_lexer -> ori_ir/diagnostic (no upward deps)

## Collaboration Protocol

When working on a plan, roadmap, or document:

1. **Draft** — Read relevant spec, code, and reference material. Produce a first draft.
2. **Consult @review** — Use the Task tool to send the draft to @review with:
   - The full draft text
   - Context: what this plan is for, what constraints apply
   - Ask: "Review this plan for completeness, correctness, feasibility, and missed edge cases. Challenge any assumptions. Propose alternatives where you disagree."
3. **Iterate** — Address @review's feedback. If you disagree with a point, explain why and re-consult. Continue until both sides reach consensus on every point.
4. **Finalize** — Present the consensus plan to the user.

Consensus means: both agents agree on every section. No unresolved disagreements. If you cannot reach consensus on a point, flag it to the user with both positions.

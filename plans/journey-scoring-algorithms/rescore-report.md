## Analysis

All 12 journeys produced different scores. This confirms the plan's central hypothesis:
AI-judged scores were inconsistent and non-reproducible. The discrepancies fall into
three systematic categories:

### 1. Instruction Ratio: "Unchecked Ideal" Bug (8 journeys improved)

The old AI used _unchecked arithmetic_ as the ideal baseline: `@add` needed only
`add` + `ret` (2 instructions), so the 7-instruction overflow-checked version scored
3.50x. The new algorithm correctly treats Ori's overflow checking as part of the ideal
instruction count (it IS what the compiler should emit), producing ~1.0x ratios.

**Affected**: J01 (3.50->1.0), J04 (1.48->1.0), J07 (2.45->1.04), J08 (2.00->1.0),
J11 (1.40->1.0). These journeys saw the biggest score *increases*.

### 2. Attribute Counting: Systematic Undercounting (all 12 journeys)

The old AI eyeballed attribute compliance and consistently undercounted the number
of applicable checks. The new algorithm has a deterministic rule table that checks
6 attributes (fastcc, nounwind, uwtable, noundef, noreturn, cold) per-function, plus
per-parameter noundef. This found 2-3x more applicable checks than the AI counted.

**Examples**: J01: 5->13 applicable, J05: 15->38, J12: 16->42.

The correct/applicable ratio also changed because the algorithm found real missing
attributes (especially `noundef` on `@main` wrapper return types and pointer params).

### 3. ARC Violations: Heap-Heavy Journeys Were Too Lenient (3 journeys worsened)

The old AI gave 0 ARC violations to journeys with closures (J05), strings (J09), and
lists (J10). The new algorithm detected real RC operation imbalances:

- **J05 (closures)**: 14 violations -- closure environments need RC inc/dec
- **J09 (strings)**: 9 violations -- string operations involve heap buffers
- **J10 (lists)**: 15 violations -- list operations have significant RC overhead

These are likely a mix of real codegen issues and conservative detection by the
heuristic `_detect_wasted_pairs` and `_detect_scalar_rc` functions. The ARC pipeline
may be correct but emitting non-obvious patterns the heuristic flags.

### Score Direction Summary

| Direction | Count | Journeys | Root Cause |
|-----------|-------|----------|------------|
| Score UP | 5 | J01, J04, J07, J08, J11 | "Unchecked ideal" bug inflated instruction ratios |
| Score DOWN | 7 | J02, J03, J05, J06, J09, J10, J12 | More thorough attribute/ARC/CF checking found real issues |

### Conclusion

The new deterministic pipeline is doing exactly what it was designed to do: eliminating
AI subjectivity. The old scores were a mix of over-penalization (instruction ratios for
checked arithmetic) and under-penalization (missing attribute checks, overlooked ARC
issues). The new scores are reproducible and explainable.

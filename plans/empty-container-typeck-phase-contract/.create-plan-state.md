### Pass 3 (Index trait end-to-end trace) — key findings

**CRITICAL REVELATION**: `Index` is NOT in the registry. It bypasses via special-cased `infer_index()` at `compiler/ori_types/src/infer/expr/structs/field_access.rs:204`. Only `set`, `insert`, `get` are in the registry; `index` uses a dedicated typechecker path + ProtocolBuiltin for ARC interception (both args Borrowed).

**`set` method IS fully user-callable TODAY**: `list.set(index: 1, value: 99)` works end-to-end (eval + LLVM). Only the SURFACE SUGAR `list[i] = v` → `list.updated(...)` is missing.

**Pattern recommendation — DO NOT follow `Index` pattern** for `IndexSet`. Follow `set` pattern:
- Registry entry with `backend_required: true`
- Normal method dispatch (NOT ProtocolBuiltin)
- Reuse existing `emit_list_set_cow` / `emit_map_insert` emitters

### Pass 4 (Prior art Rust/Swift/Go/Koka/Lean) — key findings

**Evaluation order**: Go's `safeExpr` pattern is the right model. For `state.items[i] += 1`, extract `state.items` into `let $_tmp` before desugar to avoid reading twice. This belongs in Section 11 as a specific subsection.

**Desugar placement**: Rust/Swift do post-typeck MIR/SIL lowering (because they have mutable refs/_modify). Ori's value-semantic model means desugar happens DURING `infer_assign` (type-directed). Plan is correct.

**Invalid-target detection**: Rust's `is_syntactic_place_expr` two-level gate is the right model. Syntactic (reject calls, parens, struct literals) + mutability (immutable root = E2039) + root-type (non-IndexSet-implementing = E2025).

**COW integration**: Koka/Lean's `isShared` runtime pattern maps naturally onto Ori's existing `ori_list_set_cow`'s `cow_mode` parameter. AIMS lattice Unique dimension → `cow_mode=1` (static in-place), MaybeShared → `cow_mode=0` (dynamic check). No new AIMS machinery.

### Matrix test dimensions (for Section 13)

- **TYPE**: `[T]`, `{K: V}`, `[T, max N]`, nested combinations
- **PATTERN**: simple `list[i] = v`, compound `list[i] += 1`, field `state.f = v`, mixed `state.items[i] = v`, deep chain `game.levels[i].enemies[j].hp = 0`
- **TARGET VALIDITY**: valid mutable root, immutable root (`let $x`, rejects with E2039), non-identifier root (rejects with E2042), non-IndexSet type (rejects with E2025)
- **BACKEND**: interpreter + LLVM dual-execution parity per `tests.md §Cross-Phase Verification`
- **ARC**: refcount==1 in-place, refcount>1 COW copy, zero leaks per `ORI_CHECK_LEAKS=1`

### Semantic pins (required per `tests.md §Matrix Testing Rule`)

1. `let list = [1,2,3]; list[0] = 99; assert_eq(list[0], 99)` — basic index assign works
2. `let a = [1,2,3]; let b = a; a[0] = 99; assert_eq(b[0], 1)` — COW aliasing, b unchanged
3. `let state = { items: [1,2,3] }; state.items[0] = 99; assert_eq(state.items[0], 99)` — mixed chain correctness
4. `let m = {k: 1}; m[k] += 10; assert_eq(m[k], 11)` — compound on map

### Negative pins

1. `let $x = [1,2,3]; x[0] = 99` → E2039 (assign to immutable)
2. `f()[0] = 99` → E2042 (non-place LHS)
3. `"hello"[0] = 'x'` → E2025 (str does not impl IndexSet)
4. `let list = [1]; list[0] = "wrong"` → E2001 (type mismatch)
